### Coordination design and validation

Shared `HumanReplyClaims.swift` uses same-boot monotonic-time UUID utterance IDs and user-owned0700 `~/.desktop-pets-reply-v1/`; receipt/lock files0600, owner/type/link/no-follow checks. A persistent nonblocking flock protects bounded cleanup and O_EXCL receipt creation only, never audio playback. One claimant per utterance; losing candidates yield without depending on hearing winner broadcasts. Claims are taken only after execution-time generation/master/source/hop/exclusion/busy checks. Shared scheduling allows queueing during own automatic tail while keeping manual playback priority, and preserves original .3/.2 overlap/leading-silence rules. Outgoing payload retains upstream fields plus fresh utteranceID; old/malformed/expired messages refuse autoreplies. All three responding apps must be upgraded for the guarantee.

Receipts are not released after a winner's crash or audio failure, preventing duplicate successors; this can leave an utterance unanswered. Nonblocking lock contention on independent events can also yield without delivery. IDs expire180s after issuance within the same boot; audio durations capped120s (current catalog maxima3.12/2.37/1.655s). Up to4096 live receipts plus one persistent lock; expired/prior-boot receipts pruned on later claims, no idle cleanup timer. Capacity/storage failures report and refuse autoreply, never switch to uncoordinated playback. Do not delete the active store while apps run. Same-UID malicious tampering, network filesystems and power-loss durability are outside the process-crash guarantee.

First compile exposed a test-only ambiguous Double infinity literal, corrected. First real contention test exposed macOS concurrent O_CREAT lock opens returning ENOENT; an independent20-round/8-process native reproduction observed70 such errors. Main fixed first creation using O_CREAT|O_EXCL then reopening only on EEXIST, preserving the same lock inode and failing on other errors. No assertion was relaxed; every process must return winner or ordinary loser. Each app's final self-test passes three COLD rounds of8 real processes with exactly one winner, crash-while-holding-lock persistence, lock recovery for a new utterance, all source-order permutations, independent IDs, bounded two-round graph, invalid/legacy payloads, expiry/capacity, filesystem errors and app-level cancellation/manual/automatic-tail paths. Workers use owned temporary namespaces and bounded termination; no live distributed notifications or real user preferences are used.
